# TrustFL Storage Architecture

This document explains the storage strategy and distinctions between different types of data in the TrustFL system.

## 1. Private Training Data
- **Location**: Strictly Local (Client's on-premise infrastructure)
- **Description**: The raw dataset used for training models.
- **Rule**: Never upload private datasets to any public IPFS network or centralized coordinator. TrustFL ensures this data never leaves the client's silo.

## 2. Client Model Updates
- **Location**: Off-chain Object Storage (e.g., IPFS, S3)
- **Description**: The trained parameter deltas (weights/biases) generated by a client during a training round.
- **Rule**: Stored off-chain due to size constraints. The storage URI (e.g., IPFS CID) and SHA-256 hash are recorded on the blockchain to ensure integrity.

## 3. Aggregated Global Model
- **Location**: Off-chain Object Storage (e.g., IPFS, S3)
- **Description**: The final model produced by the coordinator after aggregating all valid client updates using FedAvg.
- **Rule**: Stored off-chain. The URI and SHA-256 hash are recorded on the blockchain upon round finalization.

## 4. Public Metadata
- **Location**: On-chain (EVM Blockchain)
- **Description**: Compact verification data including client identities (public keys), round IDs, update signatures, artifact URIs (CIDs), and SHA-256 hashes.
- **Rule**: Stored permanently on the blockchain to provide an immutable, verifiable ledger of the entire federated learning lifecycle.
